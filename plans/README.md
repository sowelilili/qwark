## Findings not planned

- **`DIR_DELETE` accepts a mount root** (`src/core/net.c:365` `path_ok`,
  `:455` `rmdir_recursive`): a request for `/dev_hdd0/` recursively deletes
  everything up to five levels deep. Raised as optional hardening, not
  selected: the protocol is unauthenticated and already lets a client delete
  any file under `/dev_hdd0/`, so this would be a guard against a client bug
  rather than a boundary.

## Findings considered and rejected

So nobody re-audits them:

- **Frame handling and the request arena** (`src/core/net.c`, `conn_thread`,
  `handle_inline`, `ring_exec_locked`): every length is checked against the
  request before it is read and against the reply capacity before it is
  written; request and reply buffers never overlap. Clean.
- **USB mod take** (`src/core/modusb.c`): `.bin` names are validated, sizes
  bounded, the copy is read back and hash-checked, the swap is by rename.
  Clean.
- **`ui.pak` reader** (`src/core/uipak.c`): header, table of contents and each
  entry are bounds- and CRC-checked before use. Clean.
- **Mod rescan and pool packing** (`src/core/mods.c`): the build 58 fix
  (slices moved in pool order) reads correct; slots are kept across a rescan.
  Clean.
- **Shared scratch and text buffers** (`qscratch`, `qtext`): every user found
  is on the tick thread, or under the core lock, as `util.h` requires. Clean.
- **A mod's cave file name is not validated in the console's own library**
  (`write_cave`): documented as the client's to fill, and the file ops refuse
  `..`. By design.
- **Unauthenticated file and memory access over the LAN**: the product's
  design, not a finding.
